# Scoped editorial release security architecture

Astro static personal blog/CMS with Git content SSOT, Actions deployment, and an operator-owned Python RSS-to-Telegram outbox. Existing Vue/Worker CMS has D1 operational state and R2 media; this scoped Actions queue uses a Git journal exception and does not alter CMS auth.

Trusted actors: repository content/workflow writers, Actions with gated main-only contents write jobs, and the Hermes OS account controlling its private SQLite journal and secrets. Public readers have no queue write API. Public RSS/HTML and Telegram responses cross network trust boundaries. Baseline comparable: Git/Jekyll/Hugo CI publication and personal RSS notification services; repository/workflow writers already control publication and CI execution, so that existing capability is not a privilege escalation.

Entry points: scripts/publishing/editorial-release.ts plan/prepare/confirm CLI; src/lib/publishing/editorial-state.ts ingest/reserve/confirm; .github/workflows/deploy-pages.yml prepare/build/deploy/confirm; scripts/hermes/rss_monitor.py hourly poll or verification-only CLI. Inputs are frontmatter, full manifests, Git history, journal JSON, operator CLI/env, Actions event/vars, RSS XML, HTML canonical, SQLite state and Telegram response.

Sinks: bounded Git paths, execFileSync Git commands with argument arrays, non-force main push, Pages deployment, parameterized SQLite statements, public fetch and plaintext Telegram POST. Gates: production env flag plus main/clean/HEAD and path/symlink validation; contents write only prepare/confirm jobs in protected environment; pages workflow concurrency; remote-head check before deploy. URL origin/path allowlist, no redirects, response limits, XML DTD/entity rejection, unique canonical. Live Telegram requires CLI flag/private env and cannot use loopback; baseline initialization and URL-keyed outbox/flock dedup; uncertain intent persists before send. Dry/live state isolation and errors redact exception messages.

Review targets included failure paths, pending source revision consistency, public canonical/content-revision proof, remote-head-check/deploy race, local state file ownership and status command behavior. Pending-source and public-revision checks were added after reproducing the initial correctness gaps; REPORT.md records the final results. Git queue/source writers and same-user filesystem attackers are already privileged; distinguish reliability gaps from exploitable boundary violations. Prior audit runs were not supplied; this run covers only the introduced integration.
