## Context
Production API samples pass, but the current Pages HTML has no semantic endpoint. The automatic editorial build omits the existing public repository variable; the manual build includes it. ADR-001 and the reader-search contract already require bounded cloud search with keyword fallback.
## Goals / Non-Goals
In scope: preserve the existing endpoint through both Pages build paths, retain all release controls, and verify an unchanged public article set. Out of scope: new articles, notifications, release queue writes, new endpoint configuration, models, quotas, policy, Cron, migrations and new test infrastructure.
## Decisions
### Reuse the existing Pages workflow contract
Extend the existing workflow test to require identical endpoint forwarding in both build steps. This static check enforces the explicit build configuration boundary that caused the failure; real generated HTML separately proves the outcome. Do not add a workflow, platform or dependency. Missing configuration remains intentionally keyword-only.
## Implementation Contract
Automatic pnpm build receives PUBLIC_SEARCH_ENDPOINT from the same repository variable as manual pnpm build. Restore-before-build, source pinning, stale-main rejection, deployment permissions and schedules remain unchanged. Configured HTML contains the fixed production search URL and the reader displays real hybrid results; empty configuration produces an empty endpoint and no cloud inference. Existing source-change and unavailable-service fallback contracts remain unchanged. A deployment is accepted only if public article IDs and source revisions equal the pre-deployment snapshot. Unexpected source changes or unknown operations stop dependent work without retries or manual index triggers. Existing six-attempt production search budget remains shared across rounds; no human relevance or genuinely new-article acceptance is inferred.
## Risks / Trade-offs
A rebuild changes corpus identity even when articles are identical. Preserve stable vector namespace and let the existing Cron naturally reconcile; verify new public identity and natural receipts before final semantic browser acceptance. Missing endpoint is an allowed default, so production evidence must check the actual HTML rather than build success alone.
## Migration Plan
Pass existing full local gates and PR/exact-main CI. Compare locally generated article IDs and revisions to current public assets, then use the existing manual Pages deploy mode. Read back artifact identity and endpoint, wait for original natural reconciliation, and verify the browser. Do not trigger editorial release or send notifications. On mismatch preserve current evidence, stop and use only a reviewed compatible artifact for rollback under existing authority.
