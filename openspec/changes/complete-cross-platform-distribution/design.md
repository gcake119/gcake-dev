## Context
PR #8 provides portable preparation. D1 owns target state; Paragraph has a pinned REST service; Substack requires a dedicated Node browser runtime. The current request authorizes implementation and local dry runs, not production writes.
## Goals / Non-Goals
Goals: Preserve Git Markdown and Pages canonical (with the explicitly accepted Substack platform canonical exception), durable per-target identity, explicit approval, no emails, safe retries, and independently verified results.
Non-Goals: Deploy, merge, unattended activation, CAPTCHA bypass, private Substack APIs, or fabricate live validation.
## Decisions
### Durable checkpoints and locks
Use D1 target rows plus operation checkpoints and non-expiring ownership locks. Never steal a lock by elapsed time because the provider request can still finish. A crashed lock requires an operator to prove the process is stopped, then reconcile the checkpoint. Local SQLite only models D1 for tests; it is not a production state owner.
### Existing Paragraph REST service
Reuse ParagraphProductionService and its REST client; allow an injected verified deployment gate while retaining the controlled cohort default. Require a matching dry-run receipt, and guard create/publish before dispatch. Unknown outcomes permit read-only reconciliation only.
### Attended browser runtime
Use Playwright in Node with a dedicated persistent profile outside Git. UI contracts are configuration reviewed from live DOM, not invented defaults. Paste sanitized rendered Markdown as HTML, verify draft content/images/links and canonical/date settings, explicitly uncheck email, then perform one publish click. Missing capabilities required by the selected policy block publication.
### Public verification
Compare normalized rendered Markdown text, title, exact image/link sets, canonical, and publication timestamp. Paragraph additionally reads private and public API evidence. Do not treat an HTTP response or click as public acceptance.
## Implementation Contract
DistributionCoordinator accepts a published PortablePublication, named target, explicit operation, configuration gate, and exact revision-bound approval. It returns the independent D1 state. Dry run performs zero network writes. Create intent is persisted before dispatch; an unknown result never triggers another create. Publish intent survives verification failure and prevents another click. Approved preparation can create/update drafts; publish always validates saved content and email-off state. Unsupported/login/ambiguous UI returns manual_required. Same-revision verified repeats only verify. CLI reloads Markdown, never trusts arbitrary bundle content. Production CLI uses D1 API credentials from environment only; no cookies, source bodies, or provider diagnostics are logged. Tests use HTTP/browser fixture servers and a D1-compatible SQLite adapter, and report fixture success separately from live acceptance.
## Risks / Trade-offs
Live Substack editor selectors and canonical/date controls remain unverified until owner login; keep the live contract absent until observed. D1 lock recovery is manual to avoid overlapping writes. No automatic external write retry loop.
## Migration Plan
Apply additive checkpoint/lock migration only after deployment approval. Keep provider gates false until controlled live acceptance and explicit approval. Roll back by disabling writes; preserve D1 identities/checkpoints and never remove them during rollback.

## Accepted full-mirror continuation
In scope: Substack policy-bound review/approval; exact platform canonical and Pages original-link verification; post-publication date finalization on the original remote ID; durable metadata intent; explicit approved finalize command; anonymous complete readback. Out of scope: live publication, deployment, new provider APIs, newsletter delivery, modifying Paragraph canonical policy.

Keep legacy strict adapter mode for existing tests/callers. Full-mirror mode is explicit in UI configuration and approvals, and CLI reviews bind it. The publish intent is replaced by metadata intent before date finalization; neither intent allows another publish. Before modifying date, anonymous public content/title/assets/links/platform canonical must match (only date is temporarily exempt). Date writes require verified settings/save controls, configured timezone/format and supported precision. Retry only reads public evidence. A separately approved finalize operation can resume date writes on the same version and remote ID. Unknown publication never implies date writes without exact anonymous public evidence. Production capabilities remain unverified and writes disabled.

## Revision-scoped trial and attended side browser

Retain general production gates. A separate controlled-trial scope binds slug, sourceRevision, publication and each operation; writes are disabled by default and still require the existing review and exact approval. Paragraph reuses its REST service with a distinct trial authorization, verifies API-key publication identity before writes, and requires a saved prepared revision before trial publish. This is provisional evidence gathering, never a declaration that general capabilities are verified.

Implement the selected side browser as an adapter behind the existing coordinator. A private, per-invocation file exchange carries unique requests and bound replies; it neither runs a browser itself nor carries cookies/tokens. The operator executes visible UI using Computer Use only after the coordinator records durable intent. The adapter validates IDs, same-origin URLs, complete draft content/assets/links, saved state and no-email evidence. Anonymous public readback is independent of the attended reply and is required before verification or original-date finalization. Late or lost replies preserve checkpoints; no automatic browser write is retried.

The exchange stores only reviewed public article content and finite action evidence outside Git in 0700/0600 files. Use a fresh session for every invocation, exclusively created request/reply files and finite waits. A publish operation cannot request draft creation/update. Draft readback failure retains intent and the original ID. Trial and normal profile transports remain separate configuration choices; Node profile login is not inferred from side-browser login.

## All-article continuation contract
This section supersedes earlier single-article, no-unattended and repeated human-approval clauses for the accepted Pages-first policy. In scope: all formal Markdown candidates from gcake119/gcake-dev main, zero-write inventory, exact per-version plans, published same-ID updates, durable recovery and reviewable single-writer handover. Out of scope: original publishing, PR merge, aggregate-source backfill, MDX conversion, bulk historical provider writes and activation before handover review.

`distribution:inventory <clean-fixed-source-root> <output-json>` validates source Git identity, inventories recursive posts plus aggregate entries, anonymously proves eligible Pages and writes a complete blocked/eligible report. `planTarget` maps target state/checkpoint/lock to verify, retry, finalize, prepare/publish or blocked actions. `distribution:all-plan <source-root> <private-config> <private-output>` generates individual exact scopes using the existing schedule planner with all-formal-markdown policy, then selects operations using D1 read-only state. Each actual write reuses the existing CLI, source proof and durable coordinator. Published known-ID updates use prepare to update content then verify public evidence without publish; failed updates retain identity and checkpoint. Historic matching public Substack articles are verified/adopted without update or publish. Nonportable MDX and summary fallback are blocked rather than claiming full mirroring. New general policy is explicit, never inferred from a broad write-enabled flag. The candidate handover manifest binds file hashes and gate evidence; old runtime and schedule remain untouched until controlled switch.

## Scripted workflow implementation contract
`distribution:sync --config <policy> --pin <manifest> --acceptance <evidence> --out <private-parent> --lock <shared-outside-Git-directory> [--execute]` defaults to planning. Runtime paths derive from the script location. Use existing snapshotDistribution, prepareAllDistribution and run-distribution main. Before remote reads validate pin/policy/acceptance, then exclusively create the lock with owner metadata; no age-based takeover. Audit all D1 locks/checkpoints/intents, block any active lock, retain unknown intents in the planner. Sequential operations per platform stop after thrown failures or non-successful D1 results; the other platform continues. Finalize only from an explicit recovery plan, never as automatic replay of the previous call. If retry still fails with the preexisting metadata checkpoint, its exact finalize recovery is permitted. Save audit, plan, results, blocking reasons and cleanup result as private files. Delete only the round-owned snapshot after execution ends with no unanswered side request; retain failed-round source when a handoff is unresolved. Console emits finite handoff requests through the existing transport.

`distribution:handoff inspect|proof|reply --request <file> --config <scoped-config> --source-root <snapshot> [--evidence <observed-json>]` checks the request is physically inside its configured session directory, expiry, exact source article and trial digest, fixed source commit and D1 checkpoint/remote state for mutating actions. inspect/proof re-proves Pages; reply validates complete actual title/text/link/image/saved evidence and zero delivery flags where required. Use exclusive 0600 reply creation. No browser driver, Cookie, private API or expected-text reconstruction. CUA produces the observed JSON using visible DOM. Existing bound exchange remains the coordinator owner.
