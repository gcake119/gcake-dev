## Context
PR #8 provides portable preparation. D1 owns target state; Paragraph has a pinned REST service; Substack requires a dedicated Node browser runtime. The current request authorizes implementation and local dry runs, not production writes.
## Goals / Non-Goals
Goals: Preserve Git Markdown and Pages canonical (with the explicitly accepted Substack platform canonical exception), durable per-target identity, explicit approval, no emails, safe retries, and independently verified results.
Non-Goals: Deploy, merge, unattended activation, CAPTCHA bypass, private Substack APIs, or fabricate live validation.
## Decisions
### Durable checkpoints and locks
Use D1 target rows plus operation checkpoints and non-expiring ownership locks. Never steal a lock by elapsed time because the provider request can still finish. A crashed lock requires an operator to prove the process is stopped, then reconcile the checkpoint. Local SQLite only models D1 for tests; it is not a production state owner.
### Existing Paragraph REST service
Reuse ParagraphProductionService and its REST client; allow an injected verified deployment gate while retaining the controlled cohort default. Require a matching dry-run receipt, and guard create/publish before dispatch. Unknown outcomes permit read-only reconciliation only.
### Attended browser runtime
Use Playwright in Node with a dedicated persistent profile outside Git. UI contracts are configuration reviewed from live DOM, not invented defaults. Paste sanitized rendered Markdown as HTML, verify draft content/images/links and canonical/date settings, explicitly uncheck email, then perform one publish click. Missing capabilities required by the selected policy block publication.
### Public verification
Compare normalized rendered Markdown text, title, exact image/link sets, canonical, and publication timestamp. Paragraph additionally reads private and public API evidence. Do not treat an HTTP response or click as public acceptance.
## Implementation Contract
DistributionCoordinator accepts a published PortablePublication, named target, explicit operation, configuration gate, and exact revision-bound approval. It returns the independent D1 state. Dry run performs zero network writes. Create intent is persisted before dispatch; an unknown result never triggers another create. Publish intent survives verification failure and prevents another click. Approved preparation can create/update drafts; publish always validates saved content and email-off state. Unsupported/login/ambiguous UI returns manual_required. Same-revision verified repeats only verify. CLI reloads Markdown, never trusts arbitrary bundle content. Production CLI uses D1 API credentials from environment only; no cookies, source bodies, or provider diagnostics are logged. Tests use HTTP/browser fixture servers and a D1-compatible SQLite adapter, and report fixture success separately from live acceptance.
## Risks / Trade-offs
Live Substack editor selectors and canonical/date controls remain unverified until owner login; keep the live contract absent until observed. D1 lock recovery is manual to avoid overlapping writes. No automatic external write retry loop.
## Migration Plan
Apply additive checkpoint/lock migration only after deployment approval. Keep provider gates false until controlled live acceptance and explicit approval. Roll back by disabling writes; preserve D1 identities/checkpoints and never remove them during rollback.

## Scripted workflow implementation contract
`distribution:sync --config <policy> --pin <manifest> --acceptance <evidence> --out <private-parent> --lock <shared-outside-Git-directory> [--execute]` defaults to planning. Use exclusive 0600 reply creation. No browser driver, Cookie, private API or expected-text reconstruction. CUA produces the observed JSON using visible DOM. Existing bound exchange remains the coordinator owner.

Require safe numeric post.id, exact publication_id, canonical_url equal to requested public URL and UI origin. Native locator reads associated checkbox labels; missing boolean state still blocks. No general flags promoted and no activation before actual UI contract and scheduler qualification.

Native process binding: use Apple's documented JXA Application(processId) Apple Events target with NSRunningApplication bundle validation, in addition to window/tab IDs and origin. Name-only AppleScript can select another Chrome during headless test activity; a changed process must stop before writes. Do not terminate or adopt unrelated Chrome processes.
