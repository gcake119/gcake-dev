## Context
The handoff approves queue policy but prohibits production activation before acceptance. Git owns content and manifests; Admin runtime remains D1-owned.
## Goals / Non-Goals
Deliver gated orchestration and an installable Hermes poller. Do not change bodies, manifest order, Admin UI or configure production credentials.
## Decisions
### Git queue journal
Use a dedicated Git operational journal for this Actions-only queue, an explicit exception to the general D1 operational-state direction. Whole-branch non-force pushes reject CMS races. D1 was considered but its production configuration is not assumed. Initial readiness is reconstructed from first-parent Git commits in the current continuous eligible period, combined with complete-manifest readiness, then persisted. This preserves FIFO across multiple CMS saves within one polling interval. Missing history uses first durable observation; filesystem time is never used. Incomplete groups lose eligibility; content-only edits retain FIFO. New membership resets group readiness.
### Deployment recovery
Reserve and change publication metadata together before building. A pending attempt blocks new selection until RSS and the public page are verified. Failed builds retain the attempt for retry; published frontmatter is publication intent rather than confirmation. Use the existing pages concurrency group and latest main checkout; never force-push or merge on conflict. Check branch head before deployment. Existing push and hourly recovery stay in place. Only the latest due slot can be claimed; older missed slots are not backfilled.
### Hermes outbox
Install a standard-library Python poller under the Hermes account with a private SQLite journal and exclusive process lock. Canonical local URLs are identity, GUID is recorded as evidence. First successful feed initializes historical items silently. HTTP verifies local article HTML canonical. Claim before sending; ambiguous Telegram failure remains uncertain for manual reconciliation, never automatic resend. Dry-run uses a separate database.
## Implementation Contract
Queue JSON version 1 stores membership fingerprints and readyAt, activation startedAt, active series, completed slots and one pending attempt; it does not copy manifest order or bodies. CLI ingest/reserve/confirm operations read complete manifests and validated frontmatter, preserve raw article bodies and YAML ordering, reject unsafe paths and inconsistent states. Writes require EDITORIAL_RELEASE_ENABLED=true, main branch and workflow/environment approval. Reservation is one article at latest Monday/Thursday 07:00 Taipei, eligible at that instant. Confirmation requires expected RSS URL and successful canonical HTML carrying the transformed Markdown SHA-256. CMS pending source changes and deleted active manifests require explicit operator repair. Missing/deleted pending articles block. Manual publications are excluded; an in-progress complete group resumes before waiting groups. Workflow recovery processes pending even on pushes, but new reservations only occur on scheduled/manual runs. Hermes hourly job backs off on outages, sends title/URL/Taipei date and never sends before page verification. Verify via test:editorial, test, check, build, Python unittest and a real local static-deployment rehearsal. Remote deployment and Telegram acceptance remain human gates.
## Risks / Trade-offs
- Git push permission requires protected environment acceptance and narrowly scoped token; defaults remain disabled.
- CMS can write after the pre-deploy head check; an old artifact may briefly deploy. Pending confirmation blocks further consumption and hourly latest-head builds recover. Strong atomic Git/deployment coordination would require CMS cooperation.
- At-most-once Telegram avoids duplicate sends but ambiguous failures can lose a notification; operator reconciles privately.
- Activation requires durable ingestion before 07:00. Git commit evidence preserves existing readiness but startedAt excludes pre-activation slots. Future manually scheduled chapters cannot count as already public.
