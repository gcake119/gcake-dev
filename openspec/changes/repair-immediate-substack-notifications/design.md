## Decisions
### Preserve the existing Hermes contract
Reuse its seven public fields. For immediate publication, confirmedAt is the real approved intent instant and differenceSeconds is computed from actualAt. The message and deduplication function already treat these as confirmed/actual evidence and require no consumer installation or schema change. Distinguish the authority internally, never assert a Substack scheduled slot.
### Freeze immediate first-publication identity
Add optional publicationAuthorization with kind=immediate, operationId, authorizedAt and sourceRevision to ScheduleRecord. Only foreground explicit approval writes it. Use that immutable revision for notifications; current content verification still matches current Git. An immediate marker and armedRevision/slot or scheduled timing proof together are contradictory and rejected.
## Implementation Contract
publicationSummary preserves every existing common identity, source, current full-content, no-pending-operation and one-hour freshness guard. An immediate candidate additionally requires everPublished=true, explicit valid authorization fields, a valid authorization time no later than actualAt and no scheduled authority. Missing or invalid fields exclude the candidate; failed reads remain independently incomplete. Scheduled candidates retain their original checks and output.
The output stays exactly slug,id,revision,title,confirmedAt,actualAt,differenceSeconds. Immediate confirmedAt and actualAt are normalized to ISO UTC milliseconds before computing their interval, so the JavaScript producer and Python consumer agree even when the saved approval includes microseconds. Scheduled output remains unchanged. Existing publication_key and delivery intent/ACK logic stay unchanged. Worker acceptance tests cover both modes and invalid boundaries; the existing Python shared-monitor test proves the immediate-shaped evidence sends once and suppresses sent/intent/unknown outcomes.
Foreground reconciliation for 221099415 uses its saved approved-operation and actual public verification, validates current source and same ID again, then guarded D1 version update saves the explicit marker. It never creates a slot or armedRevision. Before delivery, inspect the existing ledger. Natural original job delivery is preferred; unknown outcomes never replay. Completion requires a positive Telegram ACK from that original flow, not subscriber receipt.
## Risks / Trade-offs
[Immediate authority could be fabricated by an operator] → require explicit foreground approval and bounded valid marker; no inference from an unscheduled draft.
[Future content updates could trigger a second notification] → freeze authorized source revision and retain existing original-ID/actual-time key.
[One-hour verification expires before the next job] → refresh complete public verification under the same immutable identity before admitting the candidate; no timer change.
No new dependencies, test layer, service, migration or per-candidate network request. Extend existing Worker and Python tests; existing local full gates qualify the code, independent deployed bundle checks qualify the Worker, and the existing natural job plus positive ACK qualifies actual notification.
