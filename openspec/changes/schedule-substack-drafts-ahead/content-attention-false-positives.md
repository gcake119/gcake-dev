# 三篇舊文內容待辦誤報：本機修正

使用者確認原本三篇「內容待同步／驗證」通知屬於誤報，並明確採用以下規則：原稿版本未變時，摘要呈現或平台格式差異不推播；確認標題、正文、連結、圖片或來源內容版本真的改變，才要求內容同步。讀取失敗保存為驗證未完成，不推論內容已改變、不編輯文章。

這是對既有通知門檻的更正。先前 attention-reasons 與 content-sync 證據描述的是當時判定及實際操作，不刪改歷史，也不再以那些紀錄宣稱本來三篇都必須編輯。本次沒有再次操作或復原三篇文章，沒有切換正式 runtime。

## 根因與修正

- 原觀察器把匿名驗證的所有例外都存成內容不符，沒有區分網路／不完整證據與真實內容差異。已有該錯誤後又直接跳過觀察，無法用新證據更正誤報。
- 新觀察結果區分嚴格驗證通過、僅呈現差異、確認內容差異、身分／時間差異與驗證未完成。保留先前已驗證版本與摘要，不把呈現相容或讀取失敗說成完整同步成功。
- 觀察專用比較略過未變來源的摘要差異，只正規化已觀察到的巢狀程式碼包裝及末尾空行標記；正文、段落結構、內部程式空白、網址、圖片與替代文字差異仍保留。Git 中真正變更的摘要仍進入前景同步。
- 前景保存／讀回的嚴格內容指紋未改。舊的未確認驗證 hold 只有在完整新證據證明相同或僅呈現差異時才解除；未結 mutation intent 與真實待辦不清除。讀取不完整使現有通知產生器保留先前快照，不產生新內容誤報。
- 沿用既有 JSON schedule document 的選用驗證欄位，無新增資料表、migration、依賴、timer、測試層或通知 schema；每篇仍最多一次匿名讀取。
