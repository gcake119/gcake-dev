## Context
Astro uses MDX/Vue and Shiki only. No diagram converter exists. The fifth article references a hand-authored SVG; its Mermaid source preserves all service relationships. CMS media-library owns uploaded immutable R2 images and D1 metadata, not repository technical diagrams. Public prose already constrains images to the reading width.

## Goals / Non-Goals
In scope: repository technical diagrams, conversion, provenance, article references and static build delivery. Out of scope: general media management, runtime Mermaid, article prose, publication state, deployment, R2/D1, required-check policy changes.

## Decisions
### Safe diagram conversion
Pin Mermaid CLI 12.0.0 (registry latest, Node >=22.13), explicitly pin Puppeteer 25.16.0 peer, commit pnpm lockfile. Local Node 22.23 and CI Node 24 satisfy the engine. Reuse installed Chrome via PUPPETEER_EXECUTABLE_PATH or explicitly install the pinned Puppeteer browser only when converting. Use strict Mermaid security, text SVG labels and opaque white background. Stage every selected output in a temporary directory and validate before replacing outputs; failed rendering never touches old files. No long-running service.

### Browser-free diagram verification
Record SHA-256 of each source/output and conversion inputs (config, converter code, package manifest and lockfile) in a sorted manifest with no timestamps or machine paths. This detects accidental drift, not malicious forgery or visual quality. Reuse marked tokenization for Markdown/MDX references, including reference-style images, rejecting raw Mermaid fences. Check local diagram links and alt text only; CMS images remain outside scope. Existing tests/build have no source-output contract. Add cheap Node checks to existing content validation/test/build scripts instead of a new CI job or full browser rerender. Cost: milliseconds per file, small manifest maintenance; actual conversion remains an author task.

### Static diagram delivery
After Astro builds, compare diagram bytes under dist with public outputs. Do not modify Astro renderer or article prose. Generate the architecture candidate first; compare against old SVG, retain directed edges and groups, and prioritize readable wrapping over geometric similarity. Existing responsive image layout and native full-size image opening support mobile; document zoom for dense architecture rather than claiming all labels are legible at thumbnail scale.

## Implementation Contract
Commands: diagrams:render <docs/diagrams/name.mmd>, diagrams:render:all, diagrams:check, diagrams:check:built. Recursion preserves relative paths; reject traversal, symlinks and non-mmd selections. Batch is sorted; an empty batch launches no browser and clears obsolete manifest entries after the last source is removed. Rendering uses local mmdc, fails nonzero with source/error, stages valid SVG before updating any output, cleans temporary files in finally. One-file rendering preserves other manifest entries. Verification rejects orphan SVG, missing/changed hashes and changed tool/config inputs, reports offending files and regeneration command. Article validation uses parsed Markdown image/fence tokens, resolves base-prefixed diagram paths, rejects missing alt, missing files and unrenderable fences. Built verification compares exact bytes. Acceptance tests use temporary repository fixtures and a fake renderer for deterministic failure paths; actual CLI conversion plus visual inspection proves the browser boundary. All temporary fixture trees are removed in finally.

### Idle executor fixture
Required CI exposed an existing process-signal fixture that spins continuously before TERM and inside the stalled handler. Replace its busy loops with shell-builtin reads on an owned FIFO prepared before the deadline. Keep 1500ms execution, 1000ms grace, TERM receipt, timeout result and process-group exit assertions unchanged. This adds two short mkfifo setup commands to the existing distribution suite, no dependency, job, service or assertion. An external sleep loop would add child startup inside the measured process group; FIFO read retains builtin-only waiting. The existing finally removes each owned directory/FIFO. Three local CPU samples per mode distinguish idle waiting from CPU saturation; targeted signal cases and complete existing gates verify retained behavior. The earlier 100ms VM guard failure remains separately recorded, with its budget unchanged.

### Post-executor media fixture
Main CI 41281935303 expired the 3000ms round before this existing media-cancellation case reached any media fetch. A diagnostic child preload delaying verify-before.mts startup by 3100ms reproduces the same mediaReads=0 failure. Only this case imports the real generated verifier in-process after writing its before observation: the real marker, parent source/media/identity checks and parent-issued verdict still execute. Native subprocess and fragmented marker coverage remain in their existing separate cases. Execution 2500ms, round 3000ms, watchdog 4500ms, slow response 6000ms and every result/state/action assertion remain unchanged. This avoids adding timers, dependencies or a duplicate verifier, and removes unrelated process startup from the specific post-executor media test. No production code or deployment workflow changes.

## Risks / Trade-offs
Chromium and Mermaid bring a substantial transitive dependency graph: skip downloads in CI and use existing Chrome only for author conversion; inspect pnpm audit and document findings without silent overrides. Hashes prove recorded consistency, not independent rerender equality. OS font differences change layout: use explicit Chinese font stack and review rendered Chinese. Tool/lock upgrades invalidate provenance and require deliberate regeneration. Hand SVG geometry will differ; report visual comparison before choosing the replacement. Rollback is a Git revert of this branch; no data migration.
